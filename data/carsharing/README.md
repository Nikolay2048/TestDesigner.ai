# Car Rental Autotest Lab

Набор синтетических материалов для проверки системы автоматического тест-дизайна и автоматической стабилизации сценариев.

## Состав

- `specs/*.md` — 5 постановок системного аналитика человеческим языком, без входных и выходных моделей.
- `openapi/openapi.yaml` — корневой OpenAPI Swagger.
- `openapi/paths/*.yaml` — операции API, подключённые через `$ref`.
- `openapi/components/*.yaml` — схемы и переиспользуемые ответы.
- `server/app.py` — мок-сервер FastAPI.
- `server/requirements.txt` — зависимости.

## Запуск сервера

```bash
cd server
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
./run.sh
```

Swagger UI мок-сервера будет доступен по адресу `http://localhost:8080/docs`.

## Основные сценарные зависимости

1. Базовая аренда эконом-класса — независимый сценарий.
2. Лояльность и дополнительные услуги — использует бронирование из сценария 1 или создаёт своё.
3. SUV с возвратом в аэропорту — независимый сценарий, но использует справочник точек.
4. Продление аренды — требует активную аренду из сценариев 1–3.
5. Возврат с инцидентом — требует активную аренду из сценариев 1–3.

## Намеренные расхождения и баги для диагностики

Эти пункты специально заложены, чтобы executor мог по ответам сервера скорректировать happy path и вернуть диагносту.

1. **Сумма preauth**: постановка говорит «сумма аренды и депозита», но не даёт точное правило. Сервер требует `paymentRequired`, вычисленный в бронировании. При ошибке возвращает `INVALID_PREAUTH_AMOUNT` и hint с точной суммой.
2. **Лояльность**: постановка использует `LC-100200`, сервер принимает только `LOYAL-GOLD-777` и возвращает hint.
3. **Возраст для SUV**: OpenAPI разрешает `driverAge >= 18`, но сервер требует `30+` для SUV.
4. **Порядок инцидента**: постановка 5 описывает возврат до регистрации инцидента, но сервер принимает инцидент только до финального закрытия аренды.
5. **Статус бронирования после создания**: сервер возвращает `DRAFT`, хотя часть постановок ожидает бизнес-состояние подтверждения. Подтверждение происходит только после `/payments/preauth`.
6. **Продление**: постановка говорит «на один день», но сервер явно валидирует дату и возвращает допустимую дату при ошибке.

## Явные баги мок-сервера

1. `POST /reservations/{reservationId}/extras` каждый повторный вызов повторно увеличивает стоимость на все extras, а не пересчитывает их идемпотентно.
2. `POST /rentals/{reservationId}/pickup` позволяет повторно выдать один и тот же reservationId несколько раз, если вызвать endpoint повторно после успешной оплаты.

## Пример happy path

```bash
curl http://localhost:8080/locations

curl -X POST http://localhost:8080/vehicles/search \
  -H 'Content-Type: application/json' \
  -d '{"pickupLocationId":"LOC-CITY-1","returnLocationId":"LOC-CITY-1","pickupDate":"2026-06-10","returnDate":"2026-06-12","driverAge":31,"category":"ECONOMY"}'
```

# Демонстрационный домен складских заказов

Домен предназначен для проверки автоматического тест-дизайна по совокупности
аналитических постановок, OpenAPI, констант окружения, исходного кода и поведения
состояниевого REST API.

## Состав

- `specs/` — пять связанных постановок на русском языке.
- `openapi/openapi.yaml` — контракт API.
- `server/` — FastAPI-сервис с бизнес-логикой по модулям.
- `server/tests/` — проверки happy path, переходов, идемпотентности и контрактов.
- `examples/happy_paths.py` — исполняемые Python-примеры всех happy path цепочек.
- `test-data.yaml` — стабильные константы тестового окружения.

## Запуск

```powershell
cd data/warehouse/server
python -m pip install -r requirements.txt
python -m uvicorn app:app --host 127.0.0.1 --port 8080
```

Сброс состояния:

```powershell
Invoke-RestMethod -Method Post http://127.0.0.1:8080/mock/reset
```

Тесты:

```powershell
cd data/warehouse/server
python -m pytest -q
```

Примеры HTTP-цепочек на Python запускаются при работающем сервере:

```powershell
cd data/warehouse
python examples/happy_paths.py all
```

Доступные режимы:

```powershell
python examples/happy_paths.py standard
python examples/happy_paths.py priority
python examples/happy_paths.py full
python examples/happy_paths.py all
```

`full` выполняет связанную цепочку `1 → 3 → 4 → 5`. Режим `all` после неё
сбрасывает состояние и отдельно выполняет сценарий 2. Базовый URL можно изменить
аргументом `--base-url`.

## Порядок сценариев и checkpoints

Сценарии 1 и 2 независимы и каждый может начинаться после reset. Сценарий 3
использует заказ и отправление из сценария 1 или 2; необходимое состояние:
заказ `READY_TO_SHIP`, отправление `PREPARED`. Сценарий 4 начинается с того же
checkpoint и доводит отправление, доставку и заказ до `DELIVERED`. Сценарий 5
использует доставленный заказ, его платёж и идентификатор одной строки.

| Сценарий | Предшественник | Сохраняемое состояние |
|---|---|---|
| Обычный заказ | нет | заказ, резерв, платёж, подготовленное отправление |
| Приоритетный заказ | нет | условия клиента, расчёт, платёж, приоритетное отправление |
| Изменение доставки | 1 или 2 | тот же заказ и подготовленное отправление с новыми реквизитами |
| Завершение доставки | 1, 2 или 3 | доставленные заказ и отправление, завершённая доставка |
| Частичный возврат | 4 | доставленный заказ, строка заказа, платёж и склад |

`POST /mock/reset` полностью восстанавливает справочники, остатки, клиентов,
счётчики и все создаваемые сущности. Для последовательности 3 → 4 → 5 reset
между сценариями не выполняется.

UC-006. Получение информации о несуществующем бронировании
Название сценария

Проверка корректного возврата ошибки при попытке получить данные бронирования по идентификатору, которого нет в системе.

1. Бизнес-контекст

Система каршеринга предоставляет возможность получить детальную информацию о бронировании по его уникальному идентификатору. Если переданный bookingId не соответствует ни одной записи в базе данных, система обязана вернуть ошибку 404, информируя клиента об отсутствии запрашиваемого ресурса.

Данный сценарий проверяет обработку крайнего случая: запрос выполняется с заведомо несуществующим идентификатором бронирования без предварительного создания какого-либо бронирования.

2. Участники сценария
Участник	Описание
Пользователь	Запрашивает информацию о бронировании с несуществующим идентификатором
API Gateway	Принимает REST-запросы клиента и маршрутизирует их
Booking Service	Выполняет поиск бронирования по идентификатору и возвращает соответствующую ошибку

3. Предусловия

Сервис доступен по REST API.
Бронирование с идентификатором "non-existent-booking" заведомо отсутствует в системе.
Никакого предварительного создания бронирований не требуется.

4. Основной поток сценария

Шаг 1. Запрос информации о несуществующем бронировании

Пользователь выполняет запрос на получение данных о бронировании, используя заведомо несуществующий идентификатор.

Метод и URL: GET /v1/bookings/non-existent-booking

Важно: значение идентификатора бронирования в URL является литеральным — "non-existent-booking". Необходимо использовать именно эту конкретную строку. Не следует предварительно создавать бронирование или использовать переменную {{bookingId}} из других сценариев.

Ожидаемый HTTP-статус ответа: 404 Not Found.

Ожидаемый код ошибки в теле ответа: BOOKING_NOT_FOUND.

Система выполняет поиск бронирования по переданному идентификатору. Поскольку запись не найдена, запрос отклоняется с ошибкой 404.

Тело ответа должно содержать:
{
  "code": "BOOKING_NOT_FOUND",
  "message": "<описание ошибки>"
}

Результат шага:

запрос отклонён системой;
система вернула HTTP 404 с кодом ошибки BOOKING_NOT_FOUND;
данные системы не изменились.

5. Постусловия

После завершения сценария:

Состояние системы не изменилось.
Никаких новых записей в системе создано не было.
Система корректно обработала запрос к несуществующему ресурсу и вернула информативное сообщение об ошибке.

6. Бизнес-правила

Система обязана проверять существование бронирования по переданному bookingId при каждом запросе на получение информации.
Если бронирование с указанным идентификатором не найдено, система должна вернуть HTTP 404 с кодом ошибки BOOKING_NOT_FOUND.
Ошибка 404 не должна раскрывать внутреннюю структуру базы данных или подтверждать существование других записей.
Запрос несуществующего бронирования не влечёт изменения состояния системы.
Все операции выполняются через REST API с использованием JSON.

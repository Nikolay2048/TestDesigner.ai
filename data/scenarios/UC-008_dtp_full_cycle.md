# UC-008. Полный цикл регистрации ДТП с двумя участниками и страховой выплатой

## Описание
Регистрация ДТП, добавление участников и транспортных средств, создание страхового дела, экспертная оценка ущерба и выплата страхового возмещения. Первый участник является виновником (CULPRIT, 100% вины), второй — пострадавшим (VICTIM). Страховое дело подаётся от имени пострадавшего. Эксперт оценивает ущерб в 78 500 руб., на основании чего создаётся и подтверждается выплата на ту же сумму.

## Предусловия
- Система ДТП доступна
- base_url настроен
- Переменные {{startDate}}, {{startDate}} доступны в контексте

## Переменные сценария

| Переменная       | Источник      | Описание                              |
|-----------------|---------------|---------------------------------------|
| accidentId       | Шаг 1         | ID созданной записи о ДТП             |
| participant1Id   | Шаг 2         | ID первого участника (виновник)       |
| participant2Id   | Шаг 4         | ID второго участника (пострадавший)   |
| vehicle1Id       | Шаг 3         | accidentVehicleId ТС первого участника|
| vehicle2Id       | Шаг 5         | accidentVehicleId ТС второго участника|
| claimId          | Шаг 6         | ID страхового дела                    |
| assessmentId     | Шаг 8         | ID запроса на экспертизу              |
| paymentId        | Шаг 11        | ID созданной выплаты                  |

## Шаги сценария

### Шаг 1 — HTTP POST, ожидаемый статус 201
Создать запись о ДТП. Передать: дату ({{startDate}}), адрес происшествия («ул. Ленина, 42»), описание («Столкновение на перекрёстке»). Сохранить accidentId из поля `accidentId` ответа.

### Шаг 2 — HTTP POST, ожидаемый статус 201
Добавить первого участника ДТП — виновника. Передать: accidentId из шага 1, имя («Иванов Иван Иванович»), телефон, номер страхового полиса, role=CULPRIT, faultPercentage=100. Сохранить participant1Id из поля `participantId` ответа.

### Шаг 3 — HTTP POST, ожидаемый статус 201
Добавить транспортное средство первого участника (виновника). Передать: accidentId, participant1Id, licensePlate («А100ВВ77»), brand («Toyota»), model («Camry»), damageAmount=45000. Сохранить vehicle1Id из поля `accidentVehicleId` ответа.

### Шаг 4 — HTTP POST, ожидаемый статус 201
Добавить второго участника ДТП — пострадавшего. Передать: accidentId из шага 1, имя («Петров Пётр Петрович»), телефон, номер страхового полиса, role=VICTIM, faultPercentage=0. Сохранить participant2Id из поля `participantId` ответа.

### Шаг 5 — HTTP POST, ожидаемый статус 201
Добавить транспортное средство второго участника (пострадавшего). Передать: accidentId, participant2Id, licensePlate («В200ММ77»), brand («Honda»), model («Civic»), damageAmount=78500. Сохранить vehicle2Id из поля `accidentVehicleId` ответа.

### Шаг 6 — HTTP POST, ожидаемый статус 201
Создать страховое дело от имени пострадавшего. Передать: accidentId, claimantParticipantId=participant2Id, claimedAmount=85000. Сохранить claimId из поля `claimId` ответа. Начальный статус дела — DRAFT.

### Шаг 7 — HTTP PATCH, ожидаемый статус 200
Обновить страховое дело: уточнить описание ущерба, сумму оставить 85000. Передать: accidentId, claimId. Тело: description=«Повреждения переднего бампера и капота в результате столкновения», claimedAmount=85000. Проверить, что статус по-прежнему DRAFT.

### Шаг 8 — HTTP POST, ожидаемый статус 201
Создать запрос на экспертную оценку ущерба по страховому делу. Передать: accidentId, claimId, expertName=«Сидоров Александр Николаевич», scheduledDate={{startDate}}. Сохранить assessmentId из поля `assessmentId` ответа.

### Шаг 9 — HTTP PATCH, ожидаемый статус 200
Внести результаты экспертизы. Передать: accidentId, claimId, assessmentId. Тело: assessedAmount=78500, report=«Осмотр проведён. Зафиксированы повреждения лакокрасочного покрытия, бампера и капота. Рыночная стоимость ремонта составляет 78 500 руб.», status=COMPLETED. После успешного ответа claim автоматически переходит в статус UNDER_REVIEW, а поле approvedAmount устанавливается равным 78500.

### Шаг 10 — HTTP GET, ожидаемый статус 200
Получить информацию о страховом деле. Передать: accidentId, claimId. Проверить: status=UNDER_REVIEW, approvedAmount=78500.

### Шаг 11 — HTTP POST, ожидаемый статус 201
Создать выплату по страховому делу. Передать: accidentId, claimId, amount=78500, recipientParticipantId=participant2Id. Сохранить paymentId из поля `paymentId` ответа. Начальный статус выплаты — PENDING.

### Шаг 12 — HTTP POST, ожидаемый статус 200
Подтвердить выплату. Передать: accidentId, claimId, paymentId. Проверить: статус выплаты стал CONFIRMED, amount=78500.

## Ожидаемые результаты
- ДТП создано и содержит двух участников и два транспортных средства
- Страховое дело подано пострадавшим (participant2Id)
- Экспертиза завершена, ущерб оценён в 78 500 руб.
- Страховое дело перешло в статус UNDER_REVIEW с approvedAmount=78500
- Выплата на сумму 78 500 руб. создана и подтверждена (статус CONFIRMED)

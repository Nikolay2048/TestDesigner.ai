UC-004. Бронирование несуществующего автомобиля
Название сценария

Проверка отклонения запроса на бронирование автомобиля, идентификатор которого отсутствует в системе.

1. Бизнес-контекст

Система каршеринга должна проверять существование автомобиля перед созданием бронирования. Если переданный vehicleId не соответствует ни одному автомобилю в базе данных, система обязана отклонить запрос с соответствующей ошибкой.

Данный сценарий проверяет корректность обработки случая, когда клиент передаёт заведомо несуществующий идентификатор автомобиля. Сценарий не требует предварительного получения списка автомобилей — запрос на бронирование отправляется напрямую с литеральным значением vehicleId.

2. Участники сценария
Участник	Описание
Пользователь	Отправляет запрос на бронирование с несуществующим vehicleId
API Gateway	Принимает REST-запросы клиента и маршрутизирует их
Booking Service	Выполняет проверку существования автомобиля и отклоняет запрос
Vehicle Service	Возвращает ошибку поиска при обращении к несуществующему автомобилю

3. Предусловия

Сервис доступен по REST API.
Пользователь с идентификатором {{user_id}} существует в системе и не заблокирован.
Автомобиль с идентификатором "vehicle-nonexistent" заведомо отсутствует в системе.
Переменная {{startDate}} содержит корректную дату в будущем в формате ISO 8601.

4. Основной поток сценария

Шаг 1. Попытка создания бронирования для несуществующего автомобиля

Пользователь отправляет запрос на бронирование, указывая идентификатор автомобиля, которого нет в системе.

Метод и URL: POST /v1/bookings

Тело запроса:
{
  "userId": "{{user_id}}",
  "vehicleId": "vehicle-nonexistent",
  "startDate": "{{startDate}}"
}

Важно: значение поля vehicleId является литеральным — "vehicle-nonexistent". Необходимо использовать именно эту конкретную строку, не заменяя её переменной из предыдущих шагов и не получая идентификатор из списка доступных автомобилей.

Ожидаемый HTTP-статус ответа: 404 Not Found.

Ожидаемый код ошибки в теле ответа: VEHICLE_NOT_FOUND.

Система выполняет проверку существования автомобиля с указанным vehicleId. Поскольку автомобиль не найден, запрос отклоняется. Никакого бронирования не создаётся.

Тело ответа должно содержать:
{
  "code": "VEHICLE_NOT_FOUND",
  "message": "<описание ошибки>"
}

Результат шага:

запрос отклонён системой;
система вернула HTTP 404 с кодом ошибки VEHICLE_NOT_FOUND;
бронирование не создано.

5. Постусловия

После завершения сценария:

Ни одно бронирование не было создано.
Данные системы не изменились.
Система корректно обработала ошибочный запрос и вернула информативное сообщение об ошибке.

6. Бизнес-правила

Система обязана проверять существование автомобиля по переданному vehicleId до выполнения каких-либо действий по созданию бронирования.
Если автомобиль с указанным vehicleId не найден, система должна вернуть HTTP 404 с кодом ошибки VEHICLE_NOT_FOUND.
При отсутствии автомобиля в базе данных бронирование не создаётся и состояние системы не изменяется.
Проверка существования автомобиля выполняется до проверки его доступности и статуса.
Все операции выполняются через REST API с использованием JSON.

UC-011. Попытка создать дублирующую страховую выплату
Название сценария

Проверка защиты от создания повторной выплаты по одному и тому же страховому делу.

1. Бизнес-контекст

Страховая система должна предотвращать дублирование выплат. После того как по страховому делу уже создана активная выплата, повторная попытка создать ещё одну выплату по тому же делу должна быть отклонена.

Данный сценарий проверяет, что система корректно распознаёт уже существующую выплату и возвращает бизнес-ошибку, не создавая второй платёж.

2. Участники сценария
Участник	Описание
Виновник ДТП	Участник, ответственный за происшествие
Пострадавший	Заявитель по страховому делу и получатель выплаты
Оператор ДТП	Регистрирует происшествие и участников
Эксперт	Подтверждает сумму ущерба
Страховая система	Создаёт выплату и контролирует отсутствие дублей

3. Предусловия

Сервис ДТП доступен.
В системе можно зарегистрировать ДТП и создать страховое дело.
Для страхового дела можно провести экспертизу и подтвердить сумму ущерба.
По одному страховому делу не должно существовать несколько активных выплат.

4. Основной поток сценария

Шаг 1. Регистрация ДТП

Оператор регистрирует ДТП с датой, местом и описанием происшествия.

Результат шага:

создана запись о ДТП;
ДТП готово к добавлению участников.

Шаг 2. Добавление виновника

Оператор добавляет участника, признанного виновником ДТП.

Результат шага:

в ДТП зарегистрирован виновник;
доля вины виновника составляет 100%.

Шаг 3. Добавление пострадавшего

Оператор добавляет пострадавшего участника.

Результат шага:

в ДТП зарегистрирован пострадавший;
пострадавший может быть заявителем по страховому делу.

Шаг 4. Создание страхового дела

Пострадавший инициирует страховое дело по зарегистрированному ДТП.

Результат шага:

создано страховое дело;
дело связано с пострадавшим участником.

Шаг 5. Проведение экспертизы

Эксперт назначает оценку ущерба, затем завершает экспертизу и подтверждает сумму ущерба.

Результат шага:

экспертиза завершена;
страховое дело готово к созданию выплаты;
подтверждённая сумма ущерба сохранена.

Шаг 6. Создание первой выплаты

Страховая система создаёт выплату по страховому делу.

Результат шага:

первая выплата создана;
выплата считается активной для данного страхового дела.

Шаг 7. Подтверждение первой выплаты

Страховая система подтверждает созданную выплату.

Результат шага:

первая выплата подтверждена;
состояние страхового дела отражает факт выполненной выплаты.

Шаг 8. Попытка создать повторную выплату

Пострадавший или оператор инициирует повторное создание выплаты по тому же страховому делу.

Результат шага:

система отклоняет повторную выплату;
ошибка указывает, что выплата по этому делу уже существует;
новая выплата не создаётся.

5. Постусловия

По страховому делу существует только исходная выплата.
Повторная выплата не создана.
Состояние исходной выплаты не изменено ошибочной повторной попыткой.

6. Бизнес-правила

По одному страховому делу не может быть создано несколько активных выплат.
Повторная попытка выплаты должна завершаться бизнес-ошибкой.
Ошибка дублирования не должна изменять уже созданную выплату.
Система должна отличать ошибку дублирования от ошибок неподходящего состояния страхового дела.

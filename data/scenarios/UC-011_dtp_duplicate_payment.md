# UC-011. Попытка создать дублирующую выплату по страховому делу

## Описание
Проверка защиты от дублирования выплат. После того как выплата по страховому делу создана и подтверждена, повторная попытка создать выплату по тому же делу должна вернуть ошибку 409 с кодом PAYMENT_ALREADY_EXISTS.

## Предусловия
- Система ДТП доступна
- base_url настроен
- Переменные {{startDate}}, {{startDate}} доступны в контексте

## Переменные сценария

| Переменная     | Источник       | Описание                               |
|---------------|----------------|----------------------------------------|
| accidentId     | Шаг 1          | ID записи о ДТП                        |
| participant1Id | Шаг 2          | ID виновника                           |
| participant2Id | Шаг 3          | ID пострадавшего                       |
| claimId        | Шаг 4          | ID страхового дела                     |
| assessmentId   | Шаг 5 (часть 1)| ID экспертизы                          |
| paymentId      | Шаг 6          | ID первой (успешной) выплаты           |

## Шаги сценария

### Шаг 1 — HTTP POST, ожидаемый статус 201
Создать запись о ДТП. Передать: дату ({{startDate}}), адрес («ул. Горького, 3»), описание («Боковое столкновение»). Сохранить accidentId из поля `accidentId` ответа.

### Шаг 2 — HTTP POST, ожидаемый статус 201
Добавить первого участника — виновника. Передать: accidentId, имя («Орлов Денис Михайлович»), телефон, номер страхового полиса, role=CULPRIT, faultPercentage=100. Сохранить participant1Id из поля `participantId` ответа.

### Шаг 3 — HTTP POST, ожидаемый статус 201
Добавить второго участника — пострадавшего. Передать: accidentId, имя («Зайцева Наталья Павловна»), телефон, номер страхового полиса, role=VICTIM, faultPercentage=0. Сохранить participant2Id из поля `participantId` ответа.

### Шаг 4 — HTTP POST, ожидаемый статус 201
Создать страховое дело от имени пострадавшего. Передать: accidentId, claimantParticipantId=participant2Id, claimedAmount=30000. Сохранить claimId из поля `claimId` ответа.

### Шаг 5 — HTTP POST + HTTP PATCH, ожидаемый статус 201 затем 200
Создать запрос на экспертизу (POST, статус 201): передать accidentId, claimId, expertName=«Федотов Юрий Анатольевич», scheduledDate={{startDate}}. Сохранить assessmentId из поля `assessmentId` ответа.
Затем завершить экспертизу (PATCH, статус 200): передать accidentId, claimId, assessmentId. Тело: assessedAmount=30000, report=«Ущерб подтверждён. Стоимость ремонта 30 000 руб.», status=COMPLETED. После этого claim переходит в статус UNDER_REVIEW с approvedAmount=30000.

### Шаг 6 — HTTP POST, ожидаемый статус 201
Создать первую выплату по страховому делу. Передать: accidentId, claimId, amount=30000, recipientParticipantId=participant2Id. Сохранить paymentId из поля `paymentId` ответа. Статус выплаты — PENDING.

### Шаг 7 — HTTP POST, ожидаемый статус 200
Подтвердить выплату. Передать: accidentId, claimId, paymentId. Проверить: статус стал CONFIRMED, amount=30000.

### Шаг 8 — HTTP POST, ожидаемый статус 409
Попытаться создать вторую выплату по тому же страховому делу. Передать: accidentId, claimId, amount=30000, recipientParticipantId=participant2Id. Ожидать: HTTP 409, в теле ответа код ошибки PAYMENT_ALREADY_EXISTS. Переменные из этого шага не извлекаются — это негативный сценарий.

## Ожидаемые результаты
- Первая выплата создана и подтверждена (CONFIRMED, 30 000 руб.)
- Повторная попытка создания выплаты возвращает 409 с кодом PAYMENT_ALREADY_EXISTS
- Состояние исходной выплаты не изменяется

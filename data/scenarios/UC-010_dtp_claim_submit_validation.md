# UC-010. Валидация подачи страхового дела: отсутствие суммы

## Описание
Проверка бизнес-валидации при попытке подать (submit) страховое дело без указания суммы требования. Система должна вернуть ошибку 400 с кодом CLAIM_AMOUNT_REQUIRED. После установки суммы повторная подача должна завершиться успехом.

## Предусловия
- Система ДТП доступна
- base_url настроен
- Переменные {{startDate}} доступны в контексте

## Переменные сценария

| Переменная     | Источник | Описание                                    |
|---------------|----------|---------------------------------------------|
| accidentId     | Шаг 1    | ID записи о ДТП                             |
| participant1Id | Шаг 2    | ID виновника                                |
| participant2Id | Шаг 3    | ID пострадавшего                            |
| accVehicleId   | Шаг 4    | accidentVehicleId ТС пострадавшего          |
| claimId        | Шаг 5    | ID страхового дела (создано без суммы)      |

## Шаги сценария

### Шаг 1 — HTTP POST, ожидаемый статус 201
Создать запись о ДТП. Передать: дату ({{startDate}}), адрес («ул. Садовая, 7»), описание («Задний удар на светофоре»). Сохранить accidentId из поля `accidentId` ответа.

### Шаг 2 — HTTP POST, ожидаемый статус 201
Добавить первого участника — виновника. Передать: accidentId, имя («Громов Василий Иванович»), телефон, номер страхового полиса, role=CULPRIT, faultPercentage=100. Сохранить participant1Id из поля `participantId` ответа.

### Шаг 3 — HTTP POST, ожидаемый статус 201
Добавить второго участника — пострадавшего. Передать: accidentId, имя («Щербакова Ольга Дмитриевна»), телефон, номер страхового полиса, role=VICTIM, faultPercentage=0. Сохранить participant2Id из поля `participantId` ответа.

### Шаг 4 — HTTP POST, ожидаемый статус 201
Добавить транспортное средство пострадавшего. Передать: accidentId, participant2Id, licensePlate («М555ТТ77»), brand («Hyundai»), model («Sonata»), damageAmount=50000. Сохранить accVehicleId из поля `accidentVehicleId` ответа.

### Шаг 5 — HTTP POST, ожидаемый статус 201
Создать страховое дело без суммы требования: передать только claimantParticipantId=participant2Id (поле claimedAmount не указывается или передаётся как null). Сохранить claimId из поля `claimId` ответа. Начальный статус — DRAFT.

### Шаг 6 — HTTP POST, ожидаемый статус 400
Попытаться подать страховое дело на рассмотрение. Endpoint: .../accidents/{accidentId}/claims/{claimId}/submit. Тело запроса пустое или без суммы. Ожидать: HTTP 400, в теле ответа код ошибки CLAIM_AMOUNT_REQUIRED. Переменные из этого шага не извлекаются — это негативный сценарий.

### Шаг 7 — HTTP PATCH, ожидаемый статус 200
Обновить страховое дело: установить claimedAmount=50000. Передать: accidentId, claimId. Тело: claimedAmount=50000. Проверить, что статус остаётся DRAFT.

### Шаг 8 — HTTP POST, ожидаемый статус 200
Повторно подать страховое дело. Endpoint: .../accidents/{accidentId}/claims/{claimId}/submit. Ожидать: HTTP 200, статус дела изменился на SUBMITTED.

## Ожидаемые результаты
- При попытке submit без суммы возвращается 400 с кодом CLAIM_AMOUNT_REQUIRED
- После установки суммы через PATCH повторный submit возвращает 200
- Статус дела переходит в SUBMITTED

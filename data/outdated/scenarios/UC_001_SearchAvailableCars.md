# UC_001 — Поиск доступных автомобилей

## Контекст

Клиент хочет арендовать автомобиль. Он открывает форму поиска, указывает город, желаемые даты аренды и свой возраст. При желании добавляет фильтр по классу. Система возвращает список доступных машин. Идентификатор выбранного автомобиля и даты аренды передаются в UC_002 для создания черновика бронирования.

---

## Сценарий

### Шаг 1 — Поиск доступных автомобилей

`GET /api/v1/cars/availability`

Клиент отправляет запрос с городом, датами аренды, возрастом водителя и опциональным фильтром по классу автомобиля. Компания работает только в двух городах — передача любого другого идентификатора города приводит к ошибке валидации. Возраст водителя ограничен страховой политикой снизу и сверху: слишком молодым и слишком пожилым водителям аренда недоступна, запросы за пределами допустимого диапазона отклоняются. Дата начала аренды обязана быть строго меньше даты окончания, и обе должны быть в будущем — некорректные интервалы также отклоняются. Если фильтр по классу не передан, в ответе возвращаются автомобили всех доступных классов. В ответе присутствуют только те машины, которые не заблокированы другими бронированиями на запрошенный период — автомобили, уже занятые конкурирующими резервами, в список не попадают. Из ответа клиент извлекает идентификатор понравившегося автомобиля для следующего шага.

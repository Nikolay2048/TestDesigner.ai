# UC_007 — Завершение аренды (возврат автомобиля)

## Контекст

Клиент возвращает автомобиль. Система фиксирует фактические показатели, рассчитывает дополнительные сборы и проводит финансовый расчёт. Идентификатор аренды передаётся из UC_004.

---

## Сценарий

### Шаг 1 — Получение данных аренды

`GET /api/v1/rentals/{rentalId}`

Система возвращает данные аренды по идентификатору из UC_004. Завершить можно только аренду в статусе ACTIVE или EXTENDED — закрытую или отменённую аренду закрыть повторно нельзя. Из ответа извлекаются сумма депозита, идентификатор автомобиля, плановые даты аренды и лимит пробега по тарифу.

---

### Шаг 2 — Фиксация возврата автомобиля

`POST /api/v1/rentals/{rentalId}/return/initiate`

Клиент передаёт фактическое время возврата, показания одометра, уровень топлива и город возврата. Финальный пробег не может быть меньше пробега, зафиксированного на момент начала аренды. Превышение включённого пробега по тарифу тарифицируется за каждый лишний километр. За возврат позже запланированного времени сверх льготного периода начисляется почасовой штраф. Если уровень топлива при возврате ниже уровня на момент выдачи, разница компенсируется по фиксированной ставке. Возврат в городе, отличном от города выдачи, влечёт межгородской сбор. По одной аренде нельзя инициировать фиксацию возврата дважды. Система возвращает идентификатор записи о возврате и перечень начисленных дополнительных сборов.

---

### Шаг 3 — Получение детализации расчёта

`GET /api/v1/rentals/{rentalId}/return/{returnId}/charges`

Система возвращает подробный расчёт: сумму депозита, перечень дополнительных сборов с описанием каждого и итоговое сальдо. Если по данной аренде было зафиксировано и принято повреждение через UC_006, его стоимость автоматически включается в список сборов. Положительное итоговое сальдо означает возврат части депозита клиенту, отрицательное — необходимость доплаты сверх депозита.

---

### Шаг 4 — Финансовый расчёт

`POST /api/v1/rentals/{rentalId}/return/{returnId}/settle`

Система проводит финансовый расчёт по записи о возврате: инициирует возврат депозита на исходный платёжный инструмент или списывает доплату с клиента. Расчёт по одному возврату проводится ровно один раз — повторная попытка возвращает ошибку конфликта. При наличии доплаты способ списания должен быть передан явно, при возврате средств — реквизиты для зачисления. Из ответа извлекается идентификатор расчёта для следующего шага.

---

### Шаг 5 — Закрытие аренды

`POST /api/v1/rentals/{rentalId}/close`

Система окончательно закрывает аренду, получая идентификатор записи о возврате (из шага 2) и идентификатор расчёта (из шага 4). Закрыть аренду можно только при наличии завершённого расчёта по данному возврату — попытка закрыть без подтверждённого расчёта отклоняется. После закрытия аренда переходит в финальный статус, автомобиль освобождается и становится доступным для других клиентов. Система возвращает итоговую сводку аренды и токен для оценки качества обслуживания.
